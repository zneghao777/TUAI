# ADR-003：React＋TypeScript＋Vite 前端与平台契约

状态：**已采纳**。用户于 2026-10-27 确认采用 React＋TypeScript＋Vite。
本决定完成 P0 前端选型；应用入口、客户端协议、组件和页面的实现仍按 P2 推进。

## 背景与决定

用户此前仅确认保留 DSH 包名和目录，要求前端暂缓；本次确认取代该暂缓状态。
产品保留自主视觉与多端基础，前端通过统一类型协议连接独立 Node Host。
具体约束与后续范围见 [Spec §14–15](../specs/项目开发规范.md#14-自主前端与组件参考)
和 [总开发计划](../../总开发计划与进度记录.md#tz-017)。

采用以下技术方向，具体版本和迁入闭包在建立前端入口时验证、锁定。

| 范围       | 决定                                                                                      |
| ---------- | ----------------------------------------------------------------------------------------- |
| 呈现与类型 | 使用 React 和 TypeScript，Web 入口采用客户端 SPA                                          |
| 开发与构建 | 使用 Vite，前端构建产物通过部署或后续桌面壳加载，业务服务继续由 Host 提供                 |
| 协议与对象 | 优先迁入并适配 DSH 的 Connection、Session、订阅、流归并与历史恢复逻辑，保持 React-free    |
| React 绑定 | 使用独立 Hooks／选择器订阅对象层；视觉组件接收普通数据、状态和回调                        |
| 样式与组件 | 采用 CSS Modules 与 CSS 设计变量，自主建立 UI Kit；参考 DSH 行为，视觉独立设计            |
| 状态与验证 | 交互 Store 只保存草稿、选中项与面板状态；沿用 Vitest，P2 引入 Playwright 验证必要界面交互 |

领域事实以 Host 和协议对象层为准，不能在全局 Store 或页面 State 中再维护独立副本。
React Hook 不进入领域包；浏览器客户端不能直接访问 Host 文件系统或执行 Cordis 服务。
如采用 Electron，Renderer 仍只使用受限平台接口，不能获得 Node／Shell 权限。

## 选择理由与边界

DSH 已有 React 组件生态与独立于 React 的连接、会话对象，使用同一呈现技术可减少
组件行为、流式更新和订阅适配的迁移成本。保留对象层与视觉层边界后，页面布局可以独立调整。
Vite 适合由独立 Host 提供业务能力的客户端应用，Web 产物也可供后续桌面壳复用。
当前产品未要求前端服务端渲染或搜索引擎收录，不在本次引入额外的服务端渲染框架。

本次不冻结页面视觉、路由库、额外状态库或第三方组件库，Electron 已于 2026-10-27 由用户确认。
按 Spec §22 的 ADR-010，P2 只验证受控 Desktop 桥契约；完整安装打包留 P7。

P0 的 TypeScript 已固定为 6.0.3，保持现状。React、ReactDOM、类型包、Vite 与
React 插件的具体版本在 TZ-017 核对 DSH 基线、Peer、Node 和构建兼容后写入清单与锁文件，
保持 React／ReactDOM、Cordis 和协议注册器的共享身份，不直接追逐最新主版本。
P2 实施锁定 React/ReactDOM 18.3.1、Vite 6.4.3、React 插件 4.7.0、TypeScript 6.0.3；
CSS Modules 与变量承担视觉，useSyncExternalStore 订阅 DSH 对象。
使用 react-markdown 10.1.0（禁用 HTML）、remark-gfm 4.0.1 和 TanStack Virtual 3.13.12；
Playwright 1.56.1 验证真实 Host 浏览器流程。依赖的用途与版本由清单、锁文件及生产构建核对。

## 已实现的平台契约

下列事实来自 TZ-005 的实现与验收，本次前端选型不改变现有配置和路径契约。

P0 已建立 Node-free 的 PlatformCapabilities、HostIdentity、HostPath 和
结构化 unavailable 契约。HostId 绑定路径，目录语义以 Host 操作系统为准。
远程客户端不能把 Host 路径解释为手机目录；当前 Web 适配器如实返回不可用。
真实目录选择、通知和桌面桥接留给后续阶段。

产品 Node 配置与凭据解析独立于 Client 包。Host 配置只保存凭据引用，
P0 仅提供显式环境变量解析器；尚未实现平台 Keychain 或加密磁盘凭据库。
解析后的密钥不会进入 Client projection、配置文件或启动日志。
不同存储适配器实现相同 CredentialResolver，后续实现无需改业务调用。

数据目录通过 TIANZHIAI_HOME 注入；否则 macOS 使用
`~/Library/Application Support/TIanZhiAi`，Windows 使用 `%APPDATA%/TIanZhiAi`，
Linux 使用 XDG config/data/state/cache 分域。目录分别管理业务库、Session、
产物、下载、浏览器 Profile、日志、缓存和临时文件。
P0 仅准备目录契约，没有创建业务库或浏览器 Profile 内容。

验证覆盖 Windows 路径纯函数、中文空格目录、Host 身份持久化、
跨 Host 路径拒绝、凭据缺失及敏感值不进入 Client。
macOS 上的路径测试不能替代 Windows 或移动端的真实安装验收。

## P2 实施补充

Host 沿用既有认证、Gateway 和生成 codec，新增 `platform.hostStatus` 提供不含凭据的
Host 身份与能力事实，`platform.artifacts` 列出会话持久引用及该会话的工具输出。
`api/artifact` 经 Connection owner 认证，并再次核验会话归属；禁止任意路径读取，
响应使用 attachment、nosniff、sandbox 与 no-store。图片通过原 Session 附件 API 读取。
此补充满足 TZ-019 的下载要求，不改变 Session 日志、默认权限或执行状态语义。

Desktop 契约只暴露目录选择与授权路径打开。主进程适配口检查调用 frame、Host、
连接代次、方法和参数；Renderer 核对回执身份，丢弃旧代次，不能获得 Node、Shell
或任意 IPC。Web 保持明确 unavailable。P2 使用受控主进程适配验证这些边界，
Electron 窗口、真实 Preload 集成、签名及安装验收仍属于 P7。
