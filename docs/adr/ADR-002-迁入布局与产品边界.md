# ADR-002：保留迁入布局与产品边界

用户于 2026-10-27 明确确认保留 DSH 包名和目录。

首批保留 `vendor/*`、`packages/<group>/<package>` 及
`@deepseek-ai/*` 名称。产品新增包使用 `@tianzhiai/*`。
Workspace 内各包只能有一个版本，不建立指向同级源码的依赖。

M0 迁入六个 Vendor 包、`util/brand`、`typert/protocol` 和
`boot/cmdline`。启动器按上游 app-boot 的 Loader、Include、Group 和
配置补丁顺序进行产品适配，仅抽取 P0 所需启动链。
完整 app-boot 的动态插件安装、官方 Bundle 目录和上游 Home 逻辑不启用。
每处适配登记原文件摘要和差异，不引入第二个 Agent Loop。

Host 与 Client 分开建立 TS project references；Client 初期只含浏览器安全契约。
前端采用 React＋TypeScript＋Vite，见 [ADR-003](ADR-003-前端选型与平台契约.md)。
P0 完成技术方向确认，前端依赖安装和界面实现留到 P2。
迁入源码保留许可及 DSH 已有补丁说明，构建配置可按当前闭包重建。

迁移归档、来源快照和说明文档不属于运行时闭包。
回滚使用对应任务提交的反向提交，不修改只读来源仓库。

P1 指令发现受产品已授权工作区边界约束。原插件允许向父目录寻找项目标记；
产品通过可选的 `projectRootBoundary` 限定向上查找，并保留工作区内的根到子目录继承。
未配置该字段时保持上游行为。该适配不扩大文件读取权限，不修改 Loop 或 Session 格式。
