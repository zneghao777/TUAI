# ADR-015：P2 换壳与交互迁移

状态：**已采纳范围调整**，依据 2026-10-27 要求及 2026-10-28 的 DSH 优先澄清。
本决定更新需求与开发计划，不表示新增迁移已经实现或验收通过。

## 背景

原 P2 以自主界面驱动 DSH 内核为出口，允许参考交互后重写。
现有底层协议可用，但文本投影、通用工具卡片和简化输入框没有保留 DSH 的完整
对话工作流。用户要求 P2 先交付简易版换壳 DSH，再继续后续改造。

源码差距、目标菜单和验收见
[P2 换壳对齐需求](../specs/appendices/P2-DSH换壳对齐需求.md)。

## 决定

P2 从“自主前端骨架”扩展为“DSH 对话工作区换壳”。
复用已迁入的协议与对象，进一步迁移上游对话投影、Composer 状态机、命令系统、
专用工具卡片及交互模块。主布局、侧栏、会话头部、过程行密度、操作入口和设置行为
也以 DSH 为准；产品层保留品牌与主题变量，不能用原简化页面限制迁移。
“参考后重写”改为有必要时才能选择，且必须保留来源和行为等价证据。

TZ-062 已接入基础服务，但 root/session Slot 仍渲染自制 App／Workspace。
后续必须用原 Conversation／Chat／Tool／Composer／Workspace 等生产组件替换对应路径，
不能把旧界面包进原 Slot 就当成换壳。显示模式、折叠偏好和权限默认值所需 settings
运行时也要接通；原“完整设置运行时不接”的旧任务边界不再排除这些必要模块。

- 保持锁定 DSH `22ddee3792402c3e70ec5f86a63c3e3e895a2f60`，不隐式升级。
- 技能界面和独立轨迹页本期不接；聊天内 reasoning 与执行记录属于必做范围。
- 迁入模型实际返回的 reasoning；没有内容时不编造，也不要求暴露未返回的内部推理。
- `/file`、`/goal`、`/plan`、`/feedback`、`/compact`、`/permission`、`/model`、
  `/export` 成套接通；`@` 文件和会话引用保留。共同能力的协议与操作语义一致。
- Host 文件／沙箱／终端、网页搜索／抓取、产物与工作区能力随实际交互补齐。
  Provider 可用性、平台能力和权限必须验证，不能通过前端占位宣称完成。
- 权限迁入仅可查看、工作区内修改、完全权限，以及真实自动审查 EXP。保留原确认、
  会话投影、命令路径、审查拒绝／失败／人工接力，不能留下静态权限标签或伪 Auto。

## 与既有架构的关系

ADR-003 的 React／TypeScript／Vite、对象／绑定／视觉分层仍适用。
此次改变的是迁移深度和 P2 验收标准，不更换前端栈或建立第二个循环。

DSH `/goal` 只管理一个 Session 的目标、修订和有界续跑；Goal 的完成不直接结算
产品 Task。P3 TaskRuntime 仍独占持久任务、父子关系、租约与结算。
P3 接入时同一执行只能有一个续跑调度入口，EngineAdapter 必须处理 Goal 与 Task
的映射或禁用重复驱动。该限制加入 TZ-026／028，不在 P2 预建 TaskRuntime。

`/plan` 的规划模式和审阅不等于 P6 Scheduler。文件／终端及 Web 工具不等于
P4 OpenMuse 浏览器。长期 Agent、团队、MCP 管理、主动通知和安装仍按原阶段推进。

权限目录按本次要求确认，不再把“可选集合待确认”当作整项阻塞。新安装无显式覆盖时
按 DSH base 使用 workspace-write＋ask；旧会话和显式配置保留，不批量扩权。
当前会话选择与新会话默认设置分开；Auto 仅供当前会话，不成为默认值。
产品原“所有 Bash 必须逐次审批、始终只读”适配须改成服从有效预设的策略，最终 guard
继续保护当前执行、资源归属与有效批准。对话权限不扩展到跨用户数据或产品凭据。
本轮只更新设计，不切换正在使用的会话。不照搬上游账户、遥测、升级渠道或用户 Profile。
反馈保存到天质当前会话；日志导出继续检查会话归属和敏感信息边界。

源码审查发现 Auto 插件热卸载会把当前 Auto 会话转为全权限。迁入时必须登记最小安全
补丁，维持拒绝执行保护或明确受限策略，不能无确认扩大权限；与上游的该差异单独验收。

## 迁移与验收影响

新增 TZ-062～069，插入原 P2 出口之前；保留已有任务 ID、旧证据及历史记录。
TZ-022 重新打开，增加 DSH-01～16 对照验收，完成后才恢复进入 P3 的默认路径。
新增迁移保留来源、闭包、补丁和回滚基点；需要替换的 M1／M3 权限适配显式登记，
不得整目录覆盖或回退鉴权、恢复、资源归属等既有保护。

当前选择的是迁移路线；最终包闭包、审查／搜索 Provider 可用性与实际 App
版本差异由对应任务核实。未满足必需行为时保持未完成，不以文档或隐藏入口替代验收。

每个任务要交付生产主界面可操作的模块和对应界面／协议证据，再勾完成。
源码复制、契约生成、旧 P2 测试通过分别记录，不能替代 DSH 操作对齐。

## TZ-063 实施适配

2026-10-28 的原对话接入保持上述边界。原 ChatView、投影和过程状态作为生产实现；
从原 apply 分出可组合入口，宿主仅注入会话跳转／文件打开，不另建模型循环或改写 Turn 事实。

显示偏好采用原 SettingsController／ConfigForms／schema／codec；当前产品 Host 的
配置所有权由窄 SettingsProvider 承接，只持久化 ui-chat 与修订号，不启用凭据控制器。
这是现有 Host 配置体系的适配，不迁入整个上游 Loader 或替换用户 Profile。
原 Markdown 通过可选配置保留天质禁止自动加载外部图片的既有边界；
默认上游行为不变，鉴权附件图库照常展示。来源补丁和行为验证见
[TZ-063 核验](../verification/TZ-063-DSH对话与过程迁移.md)。
