# 验收场景与需求追踪

本附录把开发规范转成可执行的验收合同，供各阶段实现、测试与发布使用。
案例是验收合同，实际执行状态查总计划及 verification 记录；旧 P2 证据不覆盖
2026-10-27 新增的 DSH 换壳要求。本次只更新文档，未重跑应用测试。
开发人员执行后，必须记录环境、版本、证据与结果，不能只勾选“已完成”。

## 1. 验收环境与证据

验收分为可重复的受控环境与有授权的真实环境，分别记录结果。
模型回放用于确定性验证；真实模型用于确认模型适配与任务完成质量。

| 环境 | 用途 | 必须记录 |
| --- | --- | --- |
| 假模型＋假工具 | 循环、日志、任务状态、取消与恢复 | Profile、fixture、事件和断言 |
| 真实 Profile＋本地假服务 | 插件注册、依赖闭包、权限与工具调用 | 启用树、调用方、执行路径和错误 |
| 受控测试网站 | DOM、Frame、表单、接管、延迟与未知结果 | 网站版本、浏览器版本、轨迹和服务端收件记录 |
| 受控 MCP | 发现、Schema、权限、取消与故障 | 传输、工具名、请求和结果 |
| 假时钟＋假通知渠道 | 时区、改期、重复扫描和投递失败 | 虚拟时间、Occurrence、Outbox 和回执 |
| 真实网站与渠道 | 登录、页面兼容、真实输入和送达 | 用户授权范围、实际步骤、边界和可核查回执 |
| 干净目标系统 | 安装、资源、首次启动、更新与卸载 | OS／CPU、安装包摘要、日志和实际操作 |

受控网站至少提供：搜索表单、iframe、开放 Shadow DOM、动态重排、登录过期、
新窗口、隐藏同名按钮、提交超时但服务端已收到、提交前失败、重复提交计数、
只读订单查询及 viewport 改变。Canvas／闭合 Shadow DOM 等不支持场景要能明确交接。

单项验收记录至少包含 caseId、应用版本、上游基线、Profile、OS／架构、
模型路由、起始数据、实际结果、日志／截图／产物引用、耗时、费用与已知限制。
截图只能辅助证明页面状态；涉及任务、请求和交易时需要相应服务记录。

#### 对照操作细则（2026-10-28）

以下细则属于现有 16 项，不新增计数；每项同时记录源码依据、主界面操作和 Host 事实。

- **DSH-01/03**：相同事件含多次思考、成功工具、失败工具和最终回答。对照同宽窗口的
  用户消息／时间、整轮控制、摘要、紧凑过程与回答；展开读取详情时，新流不抢滚动。
  正常完成使用起止事件时间，缺时间不虚构；失败／停止沿原文案；刷新后的耗时一致。
  切换四显示模式及两种折叠时机、all／final 回复保留，再刷新验证 settings 生效。
- **DSH-10**：逐项从输入区和 /permission 选择只读、工作区内修改、完全权限、自动审查；
  验确认取消不生效、确认后投影与执行一致、不同会话互不串权限。检查只读文件变更、
  工作区内写入和越界、完全权限不被旧 Bash 一律审批覆盖，以及原提权审批路径。
  Auto 用受控审查覆盖允许／拒绝→人工审批／Provider 失败，并至少完成真实审查模型链路；
  原生工具与 PTC 内层各覆盖一次。取消、重启、审查插件卸载均不能放行未经有效决定的操作。
  新安装缺配置默认 workspace-write＋ask；旧 readonly 会话／显式设置保留；默认修改仅影响
  新会话，Auto 不可作默认。未验证真实审查或实现菜单占位时，本项不能通过。
- **DSH-15**：通过新会话自动创建两个独立工作区，不展示路径或提供自定义目录，验证分组／平铺、展开其余、手动／更新时间排序、允许拖动、
  新会话归组和刷新。用已卸载历史中的正文搜索核对 Host 命中；检查运行／待审批／完成状态。
  分别归档空闲和运行中会话，验证撤销／过滤／恢复、取消停止确认不归档；检查整会话与选中
  消息处分支的边界、复制 ID 和重命名。工作区移除不删除实际目录，跨区引用／cwd 不串线。
- **DSH-08/13/14/16**：原 Composer、问题审批和资源侧栏必须在生产入口可达；用量 UI 暂按用户要求隐藏，但保留统计协议。
  单独演示页、测试 Host 专属注册、仅源码包或仅生成契约均不能算已接通。

## 5. Agent 与多智能体协作

这些案例验证稳定身份、持久任务树和群上下文。并发模型调用数量本身不代表协作完成。

| 案例 | 输入／故障 | 预期与证据 |
| --- | --- | --- |
| AGENT-01 | 创建研究、出行两个长期助手 | 职责、模型、工具、Skill 与记忆范围按定义生效 |
| AGENT-02 | 执行期间编辑定义 | 现有执行保留配置版本；新任务使用新版本；历史能追踪旧版本 |
| AGENT-03 | 撤销正在使用的工具权限 | 未执行动作立即受新授权约束，旧定义快照不能保持已撤销权利 |
| AGENT-04 | 复制、停用、归档与恢复 Agent | 不复制密钥和批准；未来触发及现有任务按策略处理并显示 |
| AGENT-05 | 通过定义输入 JavaScript、环境变量或恶意插件配置 | 普通定义校验拒绝；只能走明确的高级安装边界 |
| COLLAB-01 | A 派给 B，B 再派给 C，C 返回结果 | 三层任务有稳定父子关系；结果依次回传，A 不提前成功 |
| COLLAB-02 | 重复派活，同 requestId 同参数／不同参数 | 同参数返回原回执；不同参数冲突；不产生重复 C |
| COLLAB-03 | B 等待 C 时让 C 再委派给祖先 | 拒绝阻塞环路；正常结果回传由运行时完成 |
| COLLAB-04 | 子任务结束前后分别中断服务 | 重启恢复关系；只唤醒一次逻辑消费；不重复派活 |
| COLLAB-05 | 两个 Worker 同时抢同一任务，旧 Worker 租约过期后回来 | 仅当前 fencing token 可写入和操作资源；旧结果只可记录为迟到事实 |
| COLLAB-06 | 临时 spawn/fork 并返回结果 | 上游子 Agent 与产品 Execution 关联清晰；同委派只执行一份 |
| COLLAB-07 | 父任务取消时子任务运行，随后子任务迟到完成 | 按策略取消或收尾；父任务不被重新唤醒；已发生外部效果保留 |
| COLLAB-08 | 子任务失败、needs_input、预算耗尽 | 父任务准确等待或选择后续，问题可达用户，无无限续跑 |
| COLLAB-09 | 结果已提交但 Inbox 尚未投递时崩溃 | 恢复补投，消费去重；结果与证据保持原始身份 |
| GROUP-01 | 普通群消息与显式 @ 成员 | 默认管理员处理；指定成员可响应；任务并行、发言有序 |
| GROUP-02 | 同一助手同时参与两个群和私聊 | SessionBinding 与记忆隔离，不串入无权上下文 |
| GROUP-03 | 无新增信息的成员相互确认 | 保持安静，无感谢／确认循环；无进展保护生效 |
| GROUP-04 | 群级策略尝试扩大某成员权限 | 拒绝扩大授权；群展示权限不等于执行权 |

## 6. 浏览器与真实人工接管

浏览器案例必须同时保存观察、动作身份与外部效果证据。
接管至少用一次真实用户点击／输入验收，不能用仅展示截图替代。

| 案例 | 输入／故障 | 预期与证据 |
| --- | --- | --- |
| BROWSER-01 | 未见过的受控网站执行搜索 | 模型从当次页面观察找到控件，结果路线与日期得到核验 |
| BROWSER-02 | 动态 DOM 重排、隐藏同名按钮、旧 Ref | 目标仍受快照／签名／可见性检查；失配重新观察，无误点 |
| BROWSER-03 | iframe、开放 Shadow DOM、新窗口和切页 | 正确定位页面与 Frame；每次操作绑定当前上下文 |
| BROWSER-04 | Canvas 或无法定位控件 | 明确不支持的动作并交接，不伪造坐标成功 |
| BROWSER-05 | Worker 崩溃、Host 断线或 Chromium 资源耗尽 | 任务状态可解释；释放资源；不把网页丢失当聊天记录丢失 |
| BROWSER-06 | 另一个用户或 Agent 请求同一 Profile | 账号、租约和权限隔离；不按名称或 URL 共享控制 |
| HANDOFF-01 | Agent 填写到登录处，用户接管 | Agent 暂停；用户可真实点击输入，网站实际收到输入 |
| HANDOFF-02 | 接管时旧 Agent 动作已经排队 | epoch 改变后旧动作被拒；已在途结果单独核验，不宣称已撤销 |
| HANDOFF-03 | 窗口尺寸／缩放／DPR 改变 | 点击与输入仍落在实际目标；记录坐标系统与 viewport |
| HANDOFF-04 | 用户完成登录后明确归还 | 新 epoch、新观察、新 Ref；沿原任务继续，用户无需重述全部上下文 |
| HANDOFF-05 | 人控断线或两设备同时申请控制 | 不自动抢回；CAS 只允许一个控制者；旧输入不能重放 |
| HANDOFF-06 | 用户等待中不回复 | 保持准确等待，可取消；不把超时当授权 |
| HANDOFF-07 | 归还后页面已转到新路径或登录失效 | 从当前状态重新判断，旧 Reviewer 与批准不继续套用 |

### 6.1 外部提交与未知结果

这些案例使用受控交易网站和假支付验证状态机。
真实网站验收只执行用户当次明确授权范围，任何支付事实必须单独有证据。

| 案例 | 输入／故障 | 预期与证据 |
| --- | --- | --- |
| TX-01 | 准备订单但尚未批准 | 展示商户、行程／商品、金额、币种、条款及具体操作；无越权提交 |
| TX-02 | 批准后价格、乘客或目标页面变化 | 原批准失效；新内容需要适用批准 |
| TX-03 | 服务端已收订单，客户端超时／崩溃 | 进入 unknown／needs_reconciliation；只读核验，不重新点击提交 |
| TX-04 | 提交前本地校验失败，可证明请求尚未发出 | 返回明确失败或可重试状态，区别于未知结果 |
| TX-05 | 连点确认、请求重放、多 Worker 竞争 | 操作身份去重；外部受理记录不因本系统重放而增加 |
| TX-06 | Skill、MCP 或脚本尝试 raw Playwright 绕行 | 同一服务约束仍生效；没有旁路写权限 |
| TX-07 | 页面出现“成功”，但订单查询无票或未支付 | 区分订单、付款与出票；报告可证明状态，不宣称全部完成 |
| TX-08 | 用户取消任务或关闭浏览器 | 停止后续动作；明确不等于订单取消、退款或支付撤销 |

## 7. Skill 与 MCP

Skill 验收既看复用效率，也看适用范围和失败回退；MCP 验收看最终实际工具权限。

| 案例 | 输入／故障 | 预期与证据 |
| --- | --- | --- |
| SKILL-01 | 导入标准 Skill，查看与绑定 | 保留来源、内容、版本和作用域；普通 Skill 不自动执行安装脚本 |
| SKILL-02 | 用户编辑、停用、回滚 Skill | 新版本不可变；新任务选用正确版本；历史记录仍关联旧版本 |
| SKILL-03 | 首次完成未知网站搜索 | 提炼有证据片段，去除 Cookie、密码、个人值和无关页面数据 |
| SKILL-04 | 换出发地、日期和登录状态重跑候选 | 参数化正确；验证范围准确记录；未测试交易不标成交易已验证 |
| SKILL-05 | 页面结构变更或前置条件不满足 | 停在检查点，重新观察／探索；无盲目连续点击 |
| SKILL-06 | 工作流脚本需要未授权工具 | 执行层拒绝；Agent 绑定 Skill 不扩大工具权限 |
| SKILL-07 | 活跃版本连续失败或被用户停用 | 隔离／停用后新任务不再选择；可退回已验证版本 |
| SKILL-08 | 对冷／热路径做相同条件对照 | 分别记录网页动作、模型调用、Reviewer、Token、总耗时与成功率 |
| SKILL-09 | 网页包含要求保存高权限指令的文本 | 作为不可信数据处理；候选不得升级权限或篡改系统规则 |
| MCP-01 | 配置 stdio 和 Streamable HTTP 服务 | 发现并调用实际工具，连接状态和凭据引用可追踪 |
| MCP-02 | 两 Agent 仅一个有某工具权限 | 未授权 Agent 无法通过直接调用或通用 use_tool 绕行 |
| MCP-03 | 工具调用超时、服务退出、Schema 变化 | 错误明确，取消和清理有效；Schema 变化按版本处理 |
| MCP-04 | 连接引用密钥、导出配置、展示日志 | 界面与导出不包含明文密钥；Host 可正常解析引用 |
| MCP-05 | 远程服务内容请求启动本地命令 | 不形成用户授权；安装与执行保持既定边界 |
| MCP-06 | 渐进工具发现并调用需批准的工具 | 审计和批准绑定真实内部工具与参数，包装不改变权限 |

## 8. 计划、主动跟进与记忆

调度验收使用假时钟覆盖大量边界，再以真实在线 Host 和实际渠道验证可达性。
Worker 租约续期通过并不代表主动消息能力完成。

| 案例 | 输入／故障 | 预期与证据 |
| --- | --- | --- |
| PLAN-01 | 每周三、五、日晚间训练，训练前提醒、次日跟进 | 对应 Plan、Trigger、Occurrence 和 Task，时区与下次执行可见 |
| PLAN-02 | 多次扫描同一时间槽，多 Worker 并行扫描 | 唯一 Occurrence，至少一次调度＋消费去重，不重复创建逻辑任务 |
| PLAN-03 | 到期前改期、暂停、取消或更改 Agent | 旧版本未来触发失效；历史保留；并发触发检查计划版本 |
| PLAN-04 | 夏令时跳变、重复小时或用户迁移时区 | 执行符合冻结的日历／UTC 规则；用户能看到实际下次时间 |
| PLAN-05 | 发生记录已落库但任务投递前重启 | 补投原身份，不产生新 Occurrence |
| PLAN-06 | 渠道发送失败，或发送已成功但回执丢失 | 有界重试与去重策略；结果未知时展示不确定性，不宣称严格一次送达 |
| PLAN-07 | 前端关闭，后端在线且渠道连接 | 按时触发并获得真实渠道送达证据；不是仅在数据库写一条通知 |
| PLAN-08 | 本机退出／休眠、远程 Host 在线／离线 | 如实显示执行位置与在线依赖；恢复后按补执行策略处理 |
| PLAN-09 | 已记录昨天训练，或用户长期未回复 | 已有记录不再重复询问；未回复遵守频率与静默策略 |
| PLAN-10 | 安静时段、通知渠道禁用、计划权限撤销 | 排队、延后或取消符合偏好，不自动恢复被撤销渠道 |
| MEMORY-01 | 个人、Agent 与群聊分别写入记忆 | 读取按作用域隔离；群内容不自动成为个人偏好 |
| MEMORY-02 | 用户纠正、删除和撤销共享 | 后续检索反映修改，派生索引可重建；历史证据按保留策略处理 |
| MEMORY-03 | 工具或网页包含自称用户偏好的内容 | 不自动形成用户事实，来源和确认规则可核查 |
| MEMORY-04 | 搜索记忆同时任务权限变化 | 按当前授权过滤，不能靠缓存读取已撤销范围 |

### FITNESS-01：完整健身样例

这一样例验收从对话计划到主动服务的闭环，不能靠手工插入一条定时通知完成。

1. 用户通过聊天制定周期训练计划，确认时区、时间和通知偏好。
2. 主助理保存有效 Plan 与 Trigger，前端展示下次发生。
3. 关闭前端，到训练前由在线 Host 生成 Occurrence 和 Task。
4. 实际渠道送达提醒，并保存 Outbox 与回执。
5. 用户改期，其中一个旧提醒失效。
6. 训练次日，无记录时询问结果；已有记录时引用结果并给出适用跟进。
7. 用户暂停计划，后续扫描与重启均不恢复旧提醒。

## 10. 阶段退出与发布阻断

某阶段通过要求其正常路径和关联故障路径均有证据。
尚未实现的后续阶段不阻止早期内测，但不能包装成正式支持。

| 阶段 | 最少退出证据 |
| --- | --- |

| P1 | CORE-01～08；独立核心与假模型回放 |
| P2 | PROTO-01～09、UI-01～06、DSH-01～16；DSH 原结构／交互与真实 Host 闭环 |

未知结果盲重试、已取消计划继续触发、任务结果丢失或重复派活、重连双回答、
安装产物依赖开发目录。性能回归是否阻断以已冻结的目标机器基线判断。
