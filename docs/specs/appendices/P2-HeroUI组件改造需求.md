# P2：HeroUI 组件与 TUAI 视觉改造需求

> 2026-10-29 聊天导航与权限范围按[简化聊天区需求](P2-简化聊天区需求.md)覆盖；旧验收记录保留。

2026-10-29 用户将本次全界面组件改造纳入 P2。目标是在保留已有真实能力的前提下，
优先使用 HeroUI v3 重设计适合的界面组件，形成与 DSH 有区分的 TUAI 视觉。历史
TZ-022 的实现和验收记录保留；它不代表本次改造已完成。本需求与任务及综合出口见
[总计划 TZ-070～075](../../../总开发计划与进度记录.md#tz-070)。

## 1. 已确认方向与现状

- 整体专业、轻盈、克制，不花哨、不厚重；首版以中性浅色、低饱和青绿点缀和轻玻璃为方向。减少多余标语、说明文字和次要标签。
- 前端可自主调整结构和操作方式，保留 DSH 的真实功能、协议、状态和必要操作，不要求复制 DSH 外观、控件几何或操作位置。
- 语义变量与映射供多配色复用。2026-10-29 用户新增确认的晨曦浅色主题、青绿保留及持久切换，按 [TZ-077 晨曦主题需求](P2-晨曦主题需求.md)实施；既有 HeroUI 验收不覆盖本次新增主题。
- 同日用户确认纯白作为新设置的默认浅色配色，保留旧选择与局部轻玻璃，按 [TZ-082 纯白主题需求](P2-纯白主题需求.md)及独立验收实施。
- 采用 React 19、HeroUI v3 和 Tailwind CSS 4；以仓库清单与实际代码为版本事实。现有设置入口使用 HeroUI Button；其他候选不因文档列出即视为已接入。
- 已有鼠标柔光与主题初步调整仍须按本需求验收；用户要求不要读取过去的截图，实施时以当前代码和必要的实时页面为准。
- Skill 管理、独立轨迹、长期 Agent、浏览器服务等后续阶段功能不借本次改造预先启用。

## 2. 组件映射与范围

组件名称表示优先评估的 HeroUI v3 组合，具体可按实际 API、交互和无障碍测试调整。
不是将所有页面机械套成 Card，也不是让通用组件取代业务状态机。

| 区域与现有入口 | 优先选用 | 设计与保留要求 | 任务 |
| --- | --- | --- | --- |
| 基础按钮、输入、选择、开关、状态 | Button、Input、TextField、Select、Switch、Checkbox、RadioGroup、Tooltip、Spinner | 统一尺寸、文字、禁用／加载／失败和键盘焦点；保留字段验证与业务回调 | TZ-070/071 |
| 弹窗、菜单、提示 | Modal、AlertDialog、Popover、Dropdown、Toast、Alert | 按内容和风险选择，支持 Escape、焦点返回、层级和窄屏；危险操作保留独立确认，不把失败提示改成成功 | TZ-070/071/072 |
| 主题、表面、光效 | Surface、语义主题变量 | 统一浅／深色及 HeroUI／DSH 表面；玻璃集中于输入区和少量浮层，保证对比度。鼠标柔光不拦截输入，触屏和减少动态效果时停用 | TZ-070 |
| 模型选择与推理等级，`ui-model-selection` | Popover、Button、ListBox、Slider | 恢复之前模型名与推理强度集中呈现的优点；切换模型与提供商分组可用；按用户最新要求去掉弹层搜索框和管理入口，采用紧凑、低强调样式。推理等级从实际目录读取，支持模型无等级、提供商默认和非等间距语义；请求失败／加载／刷新／键盘与会话隔离清楚 | TZ-070 |
| 设置窗口与模型管理，`SettingsDialog`／`ModelSettings` | Modal、Tabs、Form、TextField、Select、AlertDialog | 优化分类、列表、编辑、测试连接、删除和保存中状态；草稿、版本冲突、真实错误、密钥保密与现有权限不退化 | TZ-071 |
| 导航、会话树、搜索、操作菜单 | Surface、Button、Tooltip、SearchField、Dropdown、Drawer | 优化侧栏、会话行和窄屏开合；保留新建、搜索、排序、置顶、重命名、分叉、归档／恢复、受管工作区和状态 | TZ-072 |
| 输入区、权限、指令和引用 | Surface、Button、Popover、Dropdown、ListBox、Kbd | 统一输入区层次与工具栏；保留四项权限及确认、`/` 命令、`@` 文件／会话引用、搜索和键盘；不将编辑器替换为普通 TextArea | TZ-072 |
| 消息、思考、工作步骤与工具 | Button、Tooltip、Disclosure、Chip、Spinner、Surface | 消息有清晰层次，工具过程默认紧凑并可展开；完整展示真实思考、命令、结果、错误、父子关系、时间与产物，不编造内容 | TZ-073 |
| 审批、问题、计划审阅 | Surface、Button、RadioGroup、Checkbox、TextField | 保留实际请求身份、多问题／自由回答、批准／拒绝、取消、过期与重连语义；普通追加输入不得视为批准 | TZ-073 |
| 附件、队列与上传 | Surface、Button、ProgressBar、Tooltip | 保留拖放、粘贴、上传状态、附件收据、队列编辑和失败重试，上传或请求未完成不显示成功 | TZ-073 |
| 上下文信息与统计 | Popover、Meter、Tooltip | 重新设计现有上下文展示，区分真实值和估算；用量统计维持既有隐藏决定，不自行恢复 | TZ-073/074 |

模型旧版控件 `apps/web/src/components/ComposerControls.tsx` 可作为当前代码中的设计参考，
它不在现有生产入口；新面板须绑定当前模型目录和 Session 真实状态。模型值和推理
等级的具体提交流程由现有对象层提供，不能维护另一份独立事实。

### 本轮实施约定（2026-10-29）

模型面板通过产品 Slot 组合现有 `ModelDirectory`，默认展示模型与推理强度，
切换视图提供分组列表；不设搜索框或管理入口，模型管理统一从侧栏设置进入。滑杆连续跟随拖动，松手后吸附到最近档位，键盘每次移动一档；仅在确认档位后提交。
滑杆只表示目录中等级的顺序，不把间距解释为
推理预算倍数；默认值、无等级模型及失败均由真实目录和提交结果决定。
通用控件由 HeroUI 适配层保持既有调用契约；复杂菜单的键盘与关闭顺序、
Lexical、工具树和文档渲染保留专用实现。以当前页面和回归结果更新完成状态。

## 3. 必须保留的专用能力

Lexical 富文本输入、IME、引用节点、草稿与队列；流式合并、Markdown、公式、代码和
安全渲染；工具树、diff、终端与文件输出；文件树及图片／PDF／表格等专用预览，
均保留现有能力，可重构其外围控件和视觉。组件库本身不提供这些业务语义。

使用现有公开契约和 Slot 在产品层组合；必要时修改迁入的 DSH 源码，按仓库来源规则
登记补丁、许可与构建依赖。不得引入第二套 Session／Agent Loop、直接绕过 Host，
或因表面替换破坏权限、鉴权、生命周期和恢复。复杂控件须核对默认焦点、层级、
外部点击及 Portal 行为，避免 HeroUI／DSH 嵌套浮层互相吞事件。

## 4. 验收与证据

各任务先通过自身验收，再由 TZ-075 综合检查。以下案例详细列在
[验收场景 UI-HERO-01～10](验收场景与需求追踪.md#42-p2-heroui-视觉改造验收)。

- 核验实际使用的 HeroUI 组件与未替换原因、语义变量、浅／深色、玻璃和鼠标柔光；确认对比度、可读性、触屏和减少动态效果。
- 在真实 Host 或受控真实链路验证模型／推理、草稿、命令、附件、权限、审批、对话流、工具结果、会话管理和文件下载；mock 不代表真实外部模型可用。
- 覆盖桌面／窄屏、键盘、焦点返回、Escape、IME、异步错误与重连；对受影响的长历史场景记录实际性能，保留现有性能门禁及测试环境。
- 记录构建、类型、共享 React 身份、来源和许可检查；若只改变视觉，仍须验证受影响交互。真实模型、其他系统、移动实机和 Electron 实壳未执行时如实列出，不能把受控测试说成目标平台验收。
- 用当前实际页面与实现验证视觉，不依赖历史截图。历史 P2 功能证据作为基线，不能直接作为本次改造验收通过的证据。
